free-agents-free-models · under the hood

Every route the tool can take

From cd project to a finished task, with every branch, every thing written to disk, and every way it can end. Read it to find what is missing.

The one invariant: a bucket is one wallet — (provider, credential). It is the unit of rate limiting, so it is the unit of scheduling. Never the agent. Two agents sharing one API key are one lane.

MAP

Six stages end to end. Sections 01–07 expand them; 08 is a path that does not exist yet, drawn so its absence is visible.

01

Setup — what lands on disk

The tool is cloned into the project as a hidden folder and adds itself to your .gitignore. Two directories, nothing else.

02

Bootstrap — credentials become lanes

Five credential sources are read, fingerprinted, and collapsed by fingerprint. This is where a shared key stops being counted twice.

What ends up in the model's context

  • The task prompt, as written
  • A prepended working-directory contract — absolute path, "use relative paths only"
  • Nothing else. No repo dump, no conversation, no other task's output.

03

Coordinator — one prompt, five routes

You paste prompts/coordinator.md once. After that you talk normally; the agent picks the route from what you ask. You never name a mode.

04

The gate — both conditions, or work directly

The second condition is the one that gets forgotten. It is about throughput, not correctness — a distinction confirmed by deliberately breaking the rule.

05

Dispatch — the loop every task goes through

One task enters. It walks a ranked chain of candidates, takes a lease on a wallet, invokes an agent, and classifies the result by who is at fault.

Why cooldowns escalate

A first failure is treated as possibly transient however severe it looks — 15 min, then 60, then 4 h, then 16 h. A genuinely dead key re-fails at once and earns the long window on its own. A blip costs minutes instead of a day.

This exists because a single transient 401 once benched a healthy 21-model wallet for 24 hours while it was answering fine.

Why local_network writes nothing

A failure you caused is not evidence about anyone's model. Without this rule, thirty seconds of bad wifi marks every model tried as dead and poisons the rankings — the only state in the system that compounds.

07

Orchestrator — many tasks, few lanes

The scheduler never launches a task it cannot place, and it replays a journal rather than trusting its own memory of what it started.

08

Cross-task memory and handoffs

not built

Workers are fully isolated today: a task sees its own spec and nothing else. Everything a previous task learned reaches the next one only as files on disk.

Why it was left out

  • Self-contained specs are what make weak models succeed — extra context is also extra to misread.
  • A summary is a lossy claim about work, and this system already learned not to trust an agent's account of itself.
  • It costs a lane call per dependency edge, on the resource that is actually scarce.
  • Tasks are file-disjoint by construction, so the common case genuinely needs nothing.

When its absence actually bites

  • B must match an interface A invented — the signature is in the file, the reasoning is not.
  • A discovered a constraint (a version pin, a broken API) that B will rediscover the hard way.
  • A chain deeper than two, where drift compounds silently.
  • Research-then-build splits, where A's whole output is the context B needs.

The cheap version, if you want it

No summariser and no extra model call: let a task write a short handoff string as part of its own result, and inject only the handoffs of tasks named in deps[]. It costs nothing on a lane, it is bounded by construction, and it degrades to today's behaviour when a task writes nothing. The expensive version — compressing raw transcripts with a model — is the part that earns its keep only on long chains.

Cold-start ordering

A fresh registry has stats for nothing — measured live, 0 of 418 models had any, so 414 tied at zero and were ordered arbitrarily. Models with no observed results are now ordered by context size, output budget, a parameter hint in the id, and an optional seed tier.

The prior applies only while a model has no stats. Clamping it below the value of one success is not enough — the spread between two priors can still offset an evidence gap — so it is gated on absence of evidence outright. Opinion orders the unknown; evidence orders everything else.

Metered lanes

copilot and cursor are a depleting monthly allowance, not an unlimited pool. Invisible unless enabled, and tried last when they are. They cannot bill you — overage is blocked, so they stop. Credits and reset date show in fa lanes -v.

EVID

What has actually been observed

Three real projects, 19 tasks, all built unattended on free models. Worth separating what has been seen from what is only tested.

ProjectShapeTasksPeak lanesWhat it proved
mdsitechain63 handoffs work — a module reported a feature the spec never asked for and its dependent matched it
fmtkitwide85 full lane saturation; 4 requeues under contention; 7 handoffs into one prompt
coldrunstarved51 9 requeues cost nothing; the journal survived; the gate is about speed, not correctness

Confirmed outside the test suite

  • Handoffs carry decisions a dependent could not otherwise discover
  • Lane leasing and full saturation across four wallets
  • no_lane requeues consume no retry budget — 13 observed, 0 attempt failures
  • The journal stays intact under repeated requeueing
  • Suitability filtering removes models that would waste a request

Still only tested, never seen

Across all three projects, not one real provider failure occurred mid-build. The circuit breaker, cooldown escalation and cross-wallet rerouting are verified by 185 mutation-tested assertions — and by nothing else.

coldrun was built to force one, by starving the scheduler to a single lane. It completed 5 of 5 anyway. This free tier is more generous than expected.

That gap should close by itself during a genuinely large build. It should not be forced by hammering providers for the sake of a test.

GAPS

What is deliberately not here

So you can tell a missing feature from a decision.

  • No token accounting. On free models the scarce resource is requests-per-credential, not tokens. Nothing counts or budgets tokens.
  • No cross-task memory. Every worker starts cold with only its spec — see stage 08 for what this costs and what adding it would take.
  • No mid-task recovery. A failed task is retried from scratch on another wallet, not resumed. Session continuity across models exists in the retired oc.sh and was not carried over.
  • No cost or quota forecasting. Health is observed, never predicted. The tool learns a wallet is cold by trying it.
  • No agent-quality ranking. Rankings are per model per category. Nothing tracks that, say, kilo follows specs better than hermes.
  • No live leaderboard. Cold ordering comes from metadata the gateways already publish, plus an optional offline data/model-seed.json you edit yourself. Nothing is fetched at runtime — leaderboards score the flagship, not the :free variant we actually call, and they cannot rank a router at all.
  • Nothing tests real models. 157 assertions run against stubs. Whether a given free model can follow a spec is not assertable — only observable.
